## v0.32.1 · 整楼多人对白一次交给 Fish（可选），太长按段落和情绪拆开；朗读页不再卡在旧楼层

### 多人对白统一提交

先说现状：之前不是整楼一次。音频一直是一段一个请求。一段里有几个人说话，本来就在同一个请求里各用各的音色（Fish S2 的多说话人），但段和段之间是分开的请求。

现在做成可选：朗读 → 02 Fish Audio →「**一次请求发多少**」。

| 选项 | 一次请求里放什么 | 什么时候出声 |
|---|---|---|
| 每段一次（默认） | 一段 | 第一段做好就播 |
| 整楼一次 | 这一楼所有角色连同旁白，各用各的音色 | 整楼做完才播 |
| 每句一次 | 一句 | 一句做好播一句 |

☞ 「整楼一次」就是你贴的那种 speakers + segments：在 Fish 上的写法是一个请求带几个音色 ID，正文里用说话人标记切换。效果一样，一场对话一次读完，人和人之间的衔接更自然。
☞ 代价：整楼做完才出声，点单句、单段也要先等整楼做好；整楼只有一个语速音量，分析给某句的快慢轻重、调音台的语速倾向在这种方式下不单独生效（情绪、语气、停顿、重读照旧）；需要 S2 系列模型。
☞ 只要对白不要旁白：「朗读范围」选「只读对白」，整楼一次就是这一楼所有人的对白放在一个请求里。
☞ 切到「整楼一次」，已经做好的音频按新方式重做一次；「每段」「每句」之间切换不重做，两者声音一样。
☞ 「整楼一次」时，段落上的「重新生成」只重做那一段，做成它自己的一条。之前这种情况下会继续播整楼那条旧的。
☞ MOSS 那个接口本身没有接。要不要再接一家语音服务商，按 9 月 16 日说好的，先问你。它那种一次提交整场对话的做法，在 Fish 上就是上面这个选项。

#### 整楼太长怎么拆

☞ 字数按发给 Fish 的原样算。情绪、语气、停顿、重读这些标签算，每次换人的说话人标记也算（`<|speaker:0|>` 一个就 13 字），句子之间的换行也算。对白来回多的楼，发出去的字能到正文的两倍多：测试里一楼 12 句、四个人，正文 183 字，发出去 422 字，其中说话人标记 156 字、情绪标签 72 字。之前只数正文，会把超长的请求当成没超。
☞ 超过「一次请求最多字数」（声音参数里，默认 1500）才拆。想整楼真的一次，就把它调大，最多 10000，Fish 一次最多收这么多。
☞ 为什么要拆得讲究：Fish 把一个请求里的长文本切成小块读，读后面一块时拿前面刚读出来的声音当参照（接口里的 condition_on_previous_chunks，默认开着），声音和语气接得上；换一个请求就从头起，前面的铺垫它听不到。所以：
  ① 能少拆就少拆。
  ② 只在段落之间拆，一段话不会被分进两个请求。只有一段自己就超过上限，才在这一段的句子之间拆。
  ③ 先挑旁白开头的段落前面：新请求从叙述起步，接下来的台词有铺垫。其次挑前后情绪一样的地方。情绪正在转折的地方尽量不拆——整楼一次要保的就是这个转折。
  ④ 拆出来的几次尽量一样长，不会拆出一个只有一两句、前面什么都没有的尾巴。几次请求同时做，一样长也就一起做完。
☞ 实测过（s2.1-pro-free 免费档）：四个音色放一个请求能读，12 句的时间戳全对得上，点单句跳得准。422 字的整楼，20 秒左右出完 36 秒的音频；楼越长等得越久，整楼做完才出声。
☞ 例子：测试里那楼，上限设 400。它从「三个人闹完，教室又安静下来」那段旁白前面切：前半是打闹，后半从安静下来开始，阿岚说要转学、班长愣住，这个情绪转折整个留在后一个请求里。不会切在阿岚那句前面，让「我下周就要转学了」冷不丁开头。

## v0.29.8 · 找到呻吟的来源了：调音台在「命令」而不是「允许」

你怀疑得对，而且不止一处。三件事叠在一起：

**1. 调音台的两项在同一次请求里互相打架。** 你把气息感拉到 80、声音表现倾向拉到 0，发出去的规则是这两句**同时存在**：

```
不要非语言声音：sounds 一律不写。
呼吸感明显：紧张、害羞、疲惫、犹豫的句子在句首加 gasping、panting 或 sighing 这类 sounds，不要每句都加。
```

模型自己挑一个听，而「这类 sounds」是一扇开着的门——它可以伸手去拿整张表里的任何一个，包括 moaning。现在：**「声音表现倾向」一项说了算加多少**，「气息感」只说用哪一种，而且当声音表现停在「不要」时，气息感那句话根本不会发出去。

**2. 那些规则在下命令。** 旧文案写的是「每三四句对白至少一处」「大多数带情绪的对白句都配一个」——这是配额，是命令。全部改成允许：「合适的地方可以写」「贴合当下的情绪就写，不必凑数」「平静的句子仍然不写」。非语言标签是这个项目要的表现手段，问题从来不是它存在，而是它被要求。

**3. 「……」→[pause] 是你自己找到的那一刀。** `不 [pause] ……又甜又酸`——一个停顿标签插进拖长的句子里，Fish 不是「停一下」，而是把那个元音**演**出来，听起来就是呻吟。推荐标点里不再包含「……」了（「！！」「？！」还在）。模型本来就听得懂省略号。

另外 moaning / groaning / panting 现在有一条硬规则：**只有原文明写了呻吟、闷哼、喘息才用**。它们没有被删掉，你手动插、标点标签照样能用。

| 偏右 | 呼吸感明显 | 声音外放 |
| 最右 | 呼吸感很重 | 声音很外放 |

中间那档是默认，含义是**这一项不写任何规则，交给分析模型按剧情自己定**。以前 50 就是这个意思，但没人看得出来。最下面的自定义规则不变，永远原样交给副模型——那仍然是最细的一层。

## 深度分析：加了一堵墙，砍掉了废话

- **单次分析最长等待**（「05 深度分析」里，默认 150 秒）：从请求发出去算起的硬上限，不管模型还在不在写。连接自己的「超时」只管「多久没动静」，而思考型模型边想边写，那个超时永远不会触发——你那次 279 秒就是这么来的。到点就停，这一楼先按现有标注读。
- 提示词里加了一条：**大多数句子只要一个情绪词就够了**，shifts / pauses / stress / sounds 是给真需要的那几句准备的；并且明说不要输出思考过程。写得少就快。
- sounds 从「原文没写但该有的也加」改成「真的会有的可以加一个，拿不准就不写，一句最多两处」。

## 顺手修的两个

- **「重新分析」认不出你打开的是哪一句**：只有从句子列表进去才算，从面板点就只剩一个「整楼都改」的单选，还取消不掉。现在你在详细页打开哪一句，它就认哪一句；没有打开任何一句时，那组单选直接不显示，文案改成明写「这次改的是整楼」。
- **「按意见改」会把深度的标注削平**：修正提示词里只列了说话人/情绪/语气/声音，模型改一句时把停顿、重读、句内转折一起丢了，所以你看到改完只剩一个标签。现在这些字段都在里面，并且写明「只动用户说到的那一项，其余照抄」。

## v0.29.5 · 缓存改成「点链接保存」，不再由程序替你点

## v0.29.2 · 超时会重试了；已有音频看得见；每层楼报一次 Fish 用量

三件事，都是同一次反馈里发现的。

**1. 「失败后自动重试次数」对超时根本没生效。** 这是个实打实的 bug。超时是靠 abort 掐掉请求实现的，而重试的循环写在了超时窗口**里面**，于是它看到一个已经 abort 的信号，当成「用户按了停止」，直接放弃——就算它想重试，也是拿着一个已经作废的信号去重试。现在循环挪到了外面，每次重试都开一个自己的超时窗口。网络抖一下不再等于这一段永久没音频。（Key 不对、余额不足、限流这些还是只问一次，重试也只是再被拒一次。）

**2. 点「从头读」看着像整楼重做。** 其实没有：已经有音频的段落一个都不会重发，程序先查本地再决定。但进度列表以前只列「正在做的那几段」，17 段里复用了 9 段、只做 8 段，看起来就像在从零开始。现在开读之前先把**每一段**都列出来，已有的直接标「已有音频」，剩下的才是要做的。

**3. 每层楼报一次 Fish 用量。** 读完或停下时，日志里写一条：「第 N 楼这次朗读向 Fish 发了 X 次请求，Y 段直接用了已有音频，Z 段没生成成功」。重试也算在 X 里，所以这个数就是真实的请求数。

顺带说一句上一版的账：有人的日志里一层楼叫了 20 多次副 API，那是旧版深度分析把整楼切成 26 批、每批一个请求造成的，每批还要重复带一遍角色卡和世界书（单批 18k token），再加上超时和空返回导致从第 1 批重来。0.29.0 之后整楼只发一次，同样的楼大概 1.4 万 token 一次就够。

## v0.28.1 · 深度分析：一句话里情绪变了就在变的地方标，声音落在词后面

按你说的改：深度分析的重点不是用程度词把情绪推高，而是把一句话拆开念，和替你做调音台上的活。

## v0.27.0 · 翻译过的楼在哪个模式下都用翻译的标注；深度分析单独成模块；段落按钮只读一段

- **不翻译 + 不分析**：程序按上下文认谁在说，不请求副模型。想让副模型认一次，点「分析这一楼」，或者在「没翻译、没分析过的楼，按播放时」里选（这个选项只在不分析模式下显示：问我一下 / 先让副模型分析一次再读 / 直接读）。

**「分析每批句数」删掉了**，整楼一次请求。

**深度分析单独成模块**（`tts-deep.js`）：提示词、请求、连接都在里面，别的地方不碰它，以后深度分析的迭代只改这一个文件。设置页也给了它自己的一栏（05 深度分析），角色卡 / 世界书 / 前几楼那几个勾也搬了进去。

**正文里段落后面的「播放」只读这一段**，读完就停，和悬浮窗里点一句只读一句一样；要一直往下读，用底栏的「朗读本楼」或悬浮窗的播放键。你截图里那个按钮是段落的按钮：只读对白时它挂在这一段最后一句对白后面，看着像句子的。

## v0.26.3 · 整楼保存也换成你的版本

「保存到本地」存整楼或整段时，遇到改过字的、单独重新生成过的句子，不再把它们的音频另附一条在后面：把各条音频解码，按朗读顺序剪拼，那一句用你的版本，前后照旧，存成一个 wav（mp3、Ogg 中间剪不开）。没有这种句子的楼还是按原格式整条存。提示里会说明这次是拼的。

音频本来就是一段一条回来的，一句只是那条音频里的一个时间区间；替换一句，就是把那条解码、剪掉这个区间、把新的那句拼进去。单句保存昨天就是这么剪的，这次把同一套用到了整楼。

## v0.26.2 · 句子里的引号词不再当对白；单句重新生成只做那一句；改过的句子在整段里也用你的版本

三条都是测试反馈。

**「想要接近」「深怕伤害」这种引号词进了对白。** 是软件的问题，不是模型的：切句子的时候把每一对引号都当成了说话，翻译时的标注又给它们配上了这一行的说话人；就算副模型说它是旁白，那句叙述也已经被切成五截、换着声音读。现在切句子时本地判断：引号里是个短语（没有句末标点、不长）、引号前面紧挨着的是字而不是冒号逗号句号、也不是「说」「道」「问」这类动词、后面也不是日语的「と」，就算作句子里的强调，并回叙述里，一句话一个声音读完。说话人着色也用同一条规则，这些词不再涂成对白的颜色。「他说“好”」「她说：“好。”」「彼は「はい」と言った」照旧是对白。

**正文里点单句的「重新生成」，整段（有时就是整楼）都重做了。** 因为单位是段，一句要重来就整段重来；正文没空行的楼一段就是一楼。现在单句重新生成只向 Fish 要那一句，做成它自己的一条音频；整段的音频留着给别的句子用，播到这一句时用新的那条。再点一次再要一次，不会拿缓存顶上。整段的「重新生成」还是整段重做。开了「生成了先不播」的，做完提示一下，不自动播。

**在悬浮窗详细页改了一句、重新生成后，从正文播整段还是旧的。** 整段音频是一条连着放的，放到那一句时并不会切换。现在播放走到有自己音频的句子（你改过的、或单独重新生成过的）就断开，用它自己的那条，放完再接回整段。「保存到本地」存整楼的替换见 v0.26.3。

## v0.26.1 · 简单分析自己认说话人，本地识别只管不分析模式；不分析模式也能点一下分析

上一版把本地认出来的说话人硬塞给简单分析，副模型改不了，等于把最不准的一环放在了最前面。这版按测试反馈改回来：

- **简单分析**：副模型自己判断谁在说，加情绪、强度、语气、语速、音量、停顿、非语言声音，一次请求全出。**调音台现在是硬约束**：每个滑杆推到两头就变成一条带数字的规则发给副模型（比如「情感强度很高：对白句全部给 emotion，一半以上写 intensity 2」「不要非语言声音：sounds 一律不写」），两头各分两档，中间不说话；提示词里写明这是要求不是参考。翻译时的骨架照旧算简单分析，零次额外调用。
- **不分析**：本地识别只在这个模式里用。这版顺手把它改准了几处：在角色写的楼里，被叫到名字的「你」不再抢说话人，只剩「她」的角色也能靠「对面是你」认出来；只有一个人在说的楼不再句句留空；引号旁写着「老板说道」这种不在角色表里的人，那句留空不乱认；翻译时的标注现在排在「引号旁的动作」这类弱证据前面，只有「某某说道」这种明写才压过它。
- **不分析模式下想让副模型认一次：**朗读页的「重新分析」在这个模式里叫「分析这一楼」，点一下只对这一楼做简单分析（说话人 + 情绪），模式不变，其他楼照旧不分析；分析过的楼以后就按分析结果读。不用再去魔法棒里改设置。
- 手动改说话人照旧最高优先，副模型和本地识别都改不了它；音色仍然是发请求那一刻按名字查表拿的。
- 「重新分析」小窗里的「说话人不对」按钮放回来了。
- 「最新一楼翻译完成后自动生成音频」改叫「最新一楼分析完自动生成音频」，做的事没变。

## v0.26.0 · 谁在说由程序认，音色随音色库走，换音色再也不会读出旧声音

这一版把「说话人」和「音色」彻底分开：说话人是人物，音色是这个人物现在绑的声音。分析结果里只有人名，没有音色 ID；音色是发请求那一刻按名字查表拿的。

**修掉的问题：改了音色库里的 Voice ID，重新生成还是旧声音。** 两个原因一起修了：

- 角色表、旁白、对白默认里存的是 ID 的拷贝，音色库里改了 ID，它们不跟着变。现在**音色库条目是本体**：你在音色库里把某个音色的 ID 改掉，所有指着它的角色、旁白、对白默认一起换过去。
- 正在读的那一楼记着打开时的音色表，改完设置再点播放 / 重新生成，用的还是旧的那份。现在每次出声前都按当前设置重新查一遍音色，分析结果原样沿用，不会再调副模型。

**音频缓存按「完整身份」找。** 一句音频记着它的文字、说话人、语言、音色、情绪、强度和你改过的内容；任何一项不同都不会拿旧的顶上。换了音色的句子一定重新生成，A 音色的音频绝不会给 B 音色用。

**新增：本地说话人识别。** 不用副模型，程序自己按上下文认谁在说：

- 引号前后的人名和「说道 / 问道 / 喊道」这类动词、引号旁边做动作的人、「顾旭禾：」这种剧本写法、上一段末尾的「某某开口道：」。
- 话里叫到的名字（「小玲，你看这个」）是被叫的人，不是说话的人。
- 场上只有两个人时，没写名字的对白按你一句我一句轮流分；出现第三个人就不再猜。
- 认不准的句子留空，用对白默认音色，不瞎猜。认人用的是角色表（含别名）、着色名单、角色卡和你的名字，所以日语原文里的「桜井」只要登记成别名，也能认到「樱井」。

由此三种模式的分工变了：

- **不分析**：0 次副模型请求，但一楼里几个人说话就几种声音——说话人本地认，认不出的用翻译时的标注，再没有才用默认音色。
- **简单分析**：说话人本地认好后**告诉**副模型，副模型只判断表演：情绪、强度、语气、语速、音量、停顿、非语言声音。它不再决定谁在说，也改不了程序已经认出来的人；只有程序留空的句子它才能补。强度和停顿现在真的会送到 Fish（沿 Fish 自己的强弱表，停顿最多两处，仍然全是官方标签）。
- 优先级：你手动指定 > 本地认出 > 翻译时的标注 > 副模型补的 > 空。

**详细页可以直接改说话人。** 顶部多了一个下拉框，列的是角色表、着色名单和角色卡里的人；选一个，这句就按那个人的音色重新生成并播放，不重新分析。旁边的灰字写着这句的说话人是怎么来的（本地识别 + 依据 / 翻译时的标注 / 副模型 / 手动指定）。「重新分析」小窗里的「说话人不对」按钮去掉了——改人不用问副模型。

**顺手修的：**整楼朗读开始时，第一段的后半截会被预取逻辑当成一个单独的段再向 Fish 要一次，现在不会了。

**内部结构：**Fish 的请求格式、标签写法、参数名收进了一个 Provider Adapter，分析层、说话人层、缓存层都不再直接碰 Fish 的格式；以后接别的语音服务只加一个适配器，说话人识别不用动。

## v0.25.1 · 单句音频能单独保存了

以前「保存到本地」只有整楼和正在读的那一段，想留一句好听的对白没办法。现在：

- 悬浮窗详细页多了一个**「保存这一句」**，点一下就存。
- 「读什么」里的「「保存到本地」保存什么」多了一项**「正在读的那一句」**，朗读页的「保存到本地」也能存单句。

**存的是你刚听到的那一条，不是重新合成的。** 同一句话 Fish 每次读得都不一样，重新要一次得到的是另一个版本；所以单句是从那一段已有的音频里按时间轴剪出来的。剪出来的存成 wav（mp3 和 ogg 按任意时刻切开会破音甚至打不开），文件名像「镜译-第12楼-樱井-第4句.wav」。你自己改过并重新生成过的句子本来就有独立音频，那种直接按原格式存。

## v0.25.0 · 重新分析可以只改一句，还能说哪里不对

**痛点：简单分析只能整楼来一遍，慢。** 说话人认错了一个、某句情绪太平，为了改这一处得让副模型把整楼重读一遍。

**现在「重新分析」会先问你。** 已经分析过（或者翻译时已经标过骨架）的楼，点悬浮窗朗读页的「重新分析」，或者详细页里新加的「改这一句的分析」，会弹一个小窗：

- **范围**：只改这一句 / 整楼都改。从详细页进来默认只改这一句。
- **哪里不对**：一个输入框，外加五个常见说法（说话人不对 / 情绪不够 / 情绪太过 / 语气太平 / 声音太多），点一下填进去，也可以自己写。
- **按意见改**：副模型拿到的是上一次的标注加你这句话，**不用再通读正文**，只改你说到的地方；没说到的句子它回一个编号，原样保留。改一句就是一个很短的请求。
- **丢掉重来（整楼）**：还是原来那条路，整楼从头分析。

没分析过、也没有骨架的楼不会弹窗，直接按原来的逻辑分析整楼——这个选项本来就只在「重新」分析时才有意义。

改动过的句子，它的音频会被丢掉，下次播放时按新的标注重做；没改的句子的音频原样保留。

**顺带说明一个误会：换角色音色不需要重新分析。** 分析结果按「正文 + 分析深度 + 语言侧」缓存，里面只有谁在说、什么情绪，不含音色 ID；音色是发请求那一刻按角色名查表的。换了音色只会让旧音频对不上、重新向 Fish 要一次，一次副模型都不会调。

## v0.24.1 · 正文里每段一对按钮：播放、重新生成

**「正文后面没有播放按钮」，这次不用再解释了。** v0.23 的回答是「手机上是故意的，去悬浮窗点」。现在不需要这个回答：按钮从每句挪到每个自然段，一段一对，电脑和手机都有。一个自然段大小的目标，拇指点得准；而一段本来就是一次 Fish 请求的单位，点它不会多花一次调用。

**播放**：从这一段读起，然后一直读下去（点某一句是只读那一句就停，两者不一样）。这一段已经生成过就直接播，没生成过就只生成这一段。

**重新生成**：丢掉这一段的音频，再向 Fish 要一次，然后播。同一段文字 Fish 每次读得都不一样，想再摇一次，在正文里点就行，不用开悬浮窗、不用进详细页。

**三档设置。**「正文处理」页的「楼层里的朗读按钮」：

- 每段一个（默认，手机也有）
- 每段一个，再加每句一个：每句后面还是原来的 ▶ 和「情绪」两个小图标
- 不显示，只在悬浮窗里点

老设置自动迁：以前的「自动（电脑显示，手机不显示）」变成每段一个，「始终显示」变成每段加每句，「不显示」不变。

**Fish 的连接设置挪了位置，加了重试。** 超时和「同时生成几段」本来在「声音参数」里，那栏是调声音的，这两项是怎么发请求，放错了地方；现在和 Key、模型、接口地址一起放在「Fish Audio」那一栏，旁边多了一个**失败后自动重试次数**（默认 1）。重试只在超时、断线和 Fish 自己出错（5xx）时发生；Key 不对、余额不足、限流（429）一次就停，再问也是同一个答复。这三项不进音频指纹，改了不会让已经生成的音频重做。

**其他**

- 按钮仍然只加在页面上，不写进楼层，正文一个字都不改。
- 双语朗读时，原文的每段和译文的每段各有一对，互不干扰。
- 正在读的那一段，它的播放按钮一直亮着，不会读到第二句就灭（以前的按钮只跟着单句亮）。
- 段落的「播放」按住不放的那一层语义补齐了：正在读时点它是暂停，暂停后再点是接着读，不是从这一段重头来。
- 修了 v0.23 的一个空指针：悬浮窗小窗上的「读这一楼」点了会报错，函数名写错了。
- 修了「重新生成」的一个硬伤：音频的对象 URL 按内容 key 缓存，新生成的那一条 key 没变，于是放回来的还是旧的那一版——花了钱，听到的还是原来那一句。现在连 URL 一起丢。
- 「重新生成」按段落单位删录音，不再按文字匹配：两段文字一模一样时，不会把另一段的音频误删。

## v0.23.0 · 三种朗读模式、标点情绪标签、悬浮窗分层、句子行的播放 / 重新生成 / 详细

按这一轮的需求和 coco 的体验报告改的。体验报告的结论先说：Fish 对「复杂形容词标签」和「复合标签」有概率读出怪气音，不在官方列表里的标签可能根本不生效，原句里的「……」也会变成怪气音。所以这版把发给 Fish 的东西收窄了：只发官方认得的英文标签，一句一个情绪词、最多加一个语气，不再发自由发挥的中文指令；标点按你配的对应表换成标签。

**三种模式（下拉框，朗读页最上面）。**

- 不分析：一次副模型都不请求。正文按引号分旁白和对白，谁在说沿用翻译时标好的说话人（没有就用对白默认音色），发给 Fish 的只有正文本身加上标点标签。最快、最省。
- 简单分析：判断每一句谁在说、什么情绪、有没有明显的语气和声音，只用 Fish 官方认得的词，一句一个情绪。开着翻译时翻译顺手就标好了（骨架里不再要中文指令，翻译输出更短），零次额外调用；不开翻译的楼按播放时问你一下（见下）。
- 深度分析：灰掉了，暂不可选。代码留着，质量迭代好再放开。存过深度的设置自动回到简单。

**没分析过的楼，按播放时问一下。** 简单模式下，一楼既没有翻译骨架也没分析过（典型：中文正文、不开翻译），你点某句播放或「朗读本楼」时弹一个小框：「先分析再读」整楼简单分析一次，之后这一楼都用它；「直接读」这一楼就按不分析读，之后不再问；勾「以后都这样」就变成设置，朗读页「没分析过的楼，按播放时」能改回来。

**标点情绪标签（调音台里的二级面板）。** 默认调音台和每个角色的调音台都多了「标点情绪标签」：左边填标点（……、！！、？！、——），右边下拉选标签（停顿、长停顿、叹气、轻笑、笑、喘息、倒吸气、抽泣、清嗓；加大音量、小声、耳语、急促；生气、开心、难过、惊讶、紧张、害怕、疑惑、困惑、温柔、害羞、兴奋、平静、严肃、冷淡、讽刺、疲惫、哀求），再选位置：「原位替换」把标点换成标签，适合停顿和声音；「放在句首」把标签放到这句前面，适合情绪和音量。「填入推荐搭配」给三条：……→停顿、！！→加大音量、？！→惊讶。发出去的是官方英文标签（[break]、[shouting]、[surprised]……），S1 用它的括号写法。不分析和简单两种模式都生效；角色没配就用默认的。

**调音台改了，音频就重做。** 录音的指纹现在包含模式、标点标签和语速倾向：换模式、改标签、拉语速倾向，下次播放就重新向 Fish 要，同一个音色能听出不同效果。语速倾向在副模型没说快慢的句子上直接变成语速参数，不分析模式下就是每句都生效。

**悬浮窗分两层。** 打开先是小窗：楼层和状态、正在做的事、播放条、「读这一楼」和「展开」；展开是原来的三页；手机上再点一次是满屏。上次的大小会记住。

**句子行尾三个按钮：播放、重新生成、详细。** 播放从这句读；重新生成丢掉这句所在那段的音频再向 Fish 要一次，改了调音台、换了音色之后用；详细进这句的页面：发给 Fish 的内容可以改，标签按钮之外多了一栏「自己写一条指令」，回车或点插入就插到光标处；译文 + 原文一起读的人在最上面能看到这句的原文。手机上键盘弹起时窗口跟着缩、正在改的框滚到中间，按钮不会被键盘盖住。

**其他**

- 简单分析的提示词换了：不再要中文指令，只要 speaker / emotion / tone / sounds / lang，情绪词、语气词、声音词只能从官方列表里选，明说不要加 slightly、very 这类程度词。
- 翻译标注一节同样只在深度模式下要 direction；简单模式下每处台词只带 head / speaker / emotion / intensity，可选 sounds（官方列表）。
- 旧楼层里已有的中文指令不再发给 Fish（深度模式除外），老录音按新指纹重做。

测试用户反馈的几条，逐条对：

**「翻译一个中文没出呢，就已经开始细读了」「没勾自动生成也在分析」。** 是 bug。悬浮窗的朗读页列句子、改句面板、翻译页的「听这段」都要先「准备」这一楼，而准备在深度模式下会直接去问副模型；悬浮窗开着的时候楼一变（翻译写回也算）就重新准备，于是翻译还没完就开始细读，流式写回的时候甚至会对半截正文细读。现在「看」和「读」分开：看楼只做本地切句、拿翻译时的骨架和已有的分析，一次副模型都不请求，列表上方会写「这一楼还没细读，按播放或「朗读本楼」时才请求」；真正请求只在按播放、点单句、「朗读本楼」、「重新细读」和勾了「自动生成音频」的时候发生。分析回来后，正在看的列表和面板自动换成细读版本。

**「日志红点无法消失」。** 以前红点是错误总数，永远不清。现在只数没看过的：打开日志页就清零，之后再有新错误才重新亮。

**「正文后没有播放按钮、没有重新生成按钮」。** 手机上是故意的（v0.21 的手机方案）：正文里默认不放每句的小按钮，单句播放和改句重生成在悬浮窗的朗读页里；要按钮的话翻译台 →「楼层里每句的按钮」选「显示」。朗读页加了一行说明。

## v0.22.0 · 配音导演：简单 / 深度两种模式、中文配音指令、角色调音台、HTML 清洗

朗读不再只是「把字读出来」。这版按今天整理的需求把分析层重做了一遍：简单分析给文本搭情绪骨架，深度分析在骨架上做配音级润色，Fish 只负责把指令演出来。

**只剩两种模式。** 「全篇发送」和「流式朗读」撤了，老设置自动迁：全篇 → 深度，流式 → 简单，「谁说的、什么情绪」那个下拉也没了，模式就是深度。音频一律一段一次 Fish 请求，几段一起发（声音参数里的「同时生成几段」），先到先播；点单句只做那一段；长楼分批分析，第一批回来就出声，下一批边播边预取。

**简单模式：让文字有情绪。** 开着翻译时零次额外调用：翻译请求里的标注要求改成要一份「情绪骨架」，每段、每句台词除了说话人、情绪词，还要一句 20 字左右的中文配音指令（`direction`：基础情绪、情绪变化、语气、语速倾向、停顿感），需要时再带重读词、停顿位置、句内转折、笑声叹气喘息这类声音。骨架存在楼层元数据里，不进正文。不开翻译、或者楼上没骨架，问一次副模型（新的「简单模式」提示词），同样的格式。

**深度模式：让情绪有因果、有演技。** 在骨架上多问一次副模型：输入是这一楼的句子、已有的骨架、角色卡、世界书、前几楼正文、各角色在前几楼最后说的话和当时的指令、角色调音台；它判断这句为什么这样说、表面和底下的情绪、和上一句是延续还是转折、说话目的、角色关系，把骨架润成配音演员能照着演的指令，重读、停顿、语速变化、呼吸笑声迟疑咳嗽都落到具体的词上，并且不让角色 OOC。省力原则照旧：骨架已经对的句子只回一个编号。「上一句的情绪只是参考，不是惯性」写进了提示词：时间跳过、换了场景、事情解决了就不延续。不开翻译时也只问一次：深度提示词自己先搭骨架再润色。调用次数：开翻译 + 简单 = 1（翻译本身），开翻译 + 深度 = 2，不开翻译 + 简单 = 1，不开翻译 + 深度 = 1。

**发给 Fish 的是中文指令。** S2 系列模型直接读 `[压着火，装冷淡，语速稍慢]` 这样的方括号，句内插 `[重读]`、`[停顿]`、`[长停顿]`、`[叹气]`、转折处插新的指令，句尾放声音；语速音量仍走 Fish 的参数。S1 读不懂自由文本，仍用它认得的英文固定标签。老楼层只有英文情绪词的照旧能读。朗读面板的标签按钮和情绪下拉换成了中文。

**角色调音台。** 「朗读 → 音色」里每个角色一套滑块：停顿感、气息感、口语颗粒度、情感强度、情绪表现幅度、语速倾向、声音表现倾向，加一栏自定义配音规则（一行一条）。还有一套默认调音台，没单独调的角色和旁白都用它。滑块中间是平常，拉到两头才会变成一句话（比如「呼吸感明显但自然：紧张、害羞、疲惫、犹豫时可以加入呼吸或喘息，不要每句都加」）交给翻译、简单、深度三处分析；数字本身不发给任何模型，Fish 也看不到。

**HTML 清洗。** 新模块 `tts-sanitizer.js`：发给 Fish 的副本先去掉 span、div、strong、em、br 等标签和 style、class 属性，解码实体，`<br>` 和段落标签变成换行，script、style、注释整块删掉。只影响副本，页面上的颜色字号照旧。「读什么」里有开关，默认开。

**TauriTavern（TT 酒馆）。** 有人在 TT 酒馆里卡在「config.yaml 改 enableCorsProxy」那步：TT 用 Rust 后端替掉了酒馆的 Node 服务，只实现了它自己的 /api 路由，没有那条通用 CORS 代理，也没有 config.yaml。镜译现在认得出自己在 TT 里（`window.__TAURITAVERN__`）：朗读页的「经酒馆 CORS 代理发送」变灰并说明原因，Fish 请求直接发、不带酒馆的会话头，发不出去时的提示改成 TT 的说法。api.fish.audio 本身不让网页直接访问，所以 TT 用户要在「接口地址」填一个自己的带跨域头的转发，使用手册第六节给了一段现成的 Cloudflare Worker 脚本。给 TauriTavern 提了个需求：加一条和酒馆 `enableCorsProxy` 等价的通用代理路由，加上之后镜译不用改就能走回代理。TT 给记忆类扩展的那套 API（找最后一条消息、全文检索、KV 存储、元数据）镜译暂时用不上：镜译的数据本来就存在楼层的 extra 和 IndexedDB 里，不扫聊天记录。

## v0.20.0 · 翻译顺手配好音、流式零请求、点单句不等整楼

**翻译的时候就把配音标好。** 朗读开着时，翻译请求里多一节标注要求：每段的说话人、情绪、语气。情绪词直接用 Fish 认得的六十个英文词（frustrated、pleading、sarcastic……）；语气从 whispering / soft tone / shouting / screaming / in a hurry tone 里选一个，只在原文写了小声、喊、急促时才写；一段里有几处台词就按顺序各标一份（`quotes`），每份带台词开头几个字，本地照着这几个字把标注对到每一句上，对不上就按顺序，再对不上就整段一份。以前这节只在「说话人着色」开着时才发，现在朗读开着也发；只开着色时还是原来的十二个词。标注照旧存在楼层的元数据里，不进正文。名单用的是朗读角色表里登记的名字，标出来的说话人直接对上音色。

**轻量分析不再请求副模型。** 「谁说的、什么情绪」里的「轻量」现在的意思是：用翻译时标好的说话人、情绪、语气直接转成 Fish 标签朗读，一次副模型都不叫；只有没标注的楼（开朗读之前翻的、或者翻译模型没回标注的）才像以前一样问一次。流式朗读默认就是轻量，所以流式一楼从头到尾零次副模型调用，出声只等 Fish。面板和步骤清单里写「用翻译时的标注」，运行记录 `tts.analysis` 记一条「没有请求副模型」。「重新细读这一楼」照旧强制问副模型。深度分析把这些标注（带 Fish 词和语气）当底色发过去，只回 id 的句子连语气也沿用；副模型自己也可以写 `tone`。

**点单句不再等整楼。** 全篇发送下点一句还没生成过的，以前要先把整楼音频做完才出声，楼一长就是几分钟。现在点单句只做它所在的那一段，几秒出声；「朗读本楼」时整楼照旧一次生成。

**整楼音频几路一起生成。** 「声音参数」里多了「同时生成几段」（默认 2，最多 4）：整楼按语速音量、字数拆成几段请求时，几段一起发给 Fish，拼回来的顺序不变，进度写「2/5 段已完成」。有一段失败就停掉其余的，报的是那一段的错。Fish 限流（429）时把它调回 1，错误提示里也写了。

**顺手修的**

- 翻译回复里的 `tone` 字段以前被当成情绪读，现在是语气；只给了 tone 没给情绪的还按情绪认。
- Fish 的六十个情绪词现在也能落到着色排版上（frustrated 按愤怒、pleading 按低落、curious 按惊讶……），以前只认十二个词，别的词着色时当没标。朗读那边发给 Fish 的仍是原词。
- S1 模型：Fish 词表里有、又能折到十二色的词（frustrated）发原词；十二色本身的词（angry）仍按 S1 的强度列写。

**细读太慢**

- **分批并行**：一楼超过 30 句时，细读按段落边界切成几批一起发，批数 = 副 API 通道的「并发数」（翻译那边同一个设置，默认 1，要并行得先调高），每批带上前面紧挨着的三句当语气参考，只看不答。三路并发读 36 句，等的时间大约是原来的三分之一。运行记录里 `tts.analysis` 按批记，`tts.analysis-batches` 记总时间。轻量分析同样分批。
- **分析用的副 API**（朗读页「读什么」）：细读、轻量分析、从世界书识别角色可以单独走另一条通道，比如一个更快更便宜的模型，不占翻译那条。默认跟随翻译的模型设置；选的通道被删掉了就自动跟回去。
- **内置提示词可复制**：「副模型提示词（高级）」里每套提示词多了「填入内置的再改」和「复制内置提示词」；朗读面板多了「复制这一楼的分析」，把每句的说话人、情绪、配音指令和发给 Fish 的文本复制成 JSON。

**进度条能拖**：悬浮窗朗读页的进度条变成滑块，点一下跳过去，按住拖着走，键盘左右键每次 5%。播放中、暂停中都能拖（暂停时拖到头不会自己接着放下一句）；读完了再拖，就从那一句重新读。手机上滑块加粗。

## v0.18.0 · 朗读：音色库、两种模式、副模型细读配音、悬浮窗朗读面板

朗读这一版的目标是让音频更有灵魂，同时减少重复调用。

不知道从哪开始的话，先看 [使用手册](使用手册.md)。

**两种模式，单句发送并入了。**

- **全篇发送**：副模型带着角色卡、世界书和前几楼剧情细读整楼，给每一句写配音指令；整楼一次生成，每句记时间，点哪句跳哪句。情绪最饱满，但要等副模型读完。
- **流式朗读**：按段（一个自然段一个请求）生成，第一段回来就开始播，后面的段边播边生成；副模型只做轻量分析（谁说的、什么情绪）。出声快，情绪标签少。
- 原来的「单句发送」不再单独存在：点某一句时，先在已有的音频里找这一句（整楼的、某一段的都算），找到就直接跳过去播；找不到才生成这一句所在的段。**这也修了「整篇转过音后点单句仍然重新请求」**：以前整篇和单句是两套缓存互不认识，现在每条录音都记着自己包含哪些句子、用的什么音色，换模式也能互相复用。

**副模型细读配音（Voice JSON）。** 全篇发送时，副模型不只标一个情绪词，而是按三十来项写结构化的配音指令：基础情绪、次级情绪、强度、走向、心理状态、说话意图、潜台词、自我克制、语速、音高、音量、能量、紧张、呼吸感、嘶哑、犹豫、停顿位置、重音词、句内情绪变化、非语言声音（叹气 / 倒吸气 / 哽咽……）、结尾方式、紧迫程度、表演方式、声音重点，外加整楼的场景和每个人物的状态与说话习惯。镜译在本地把这些编译成 Fish 认得的英文标签：情绪按 Fish 自己的强度表写成 `[very frustrated]`，音量小加 `[soft tone]` 或 `[whispering]`，压着情绪加 `[holding back]`，停顿处插 `[break]`，重音词前插 `[emphasis]`，句内变化在那个词前换标签，叹气放句首；语速和音量是 Fish 按请求生效的参数，所以语速或音量不同的句子会自动拆成单独的请求（可关）。台词本身依旧不经过模型，一个字不改。同一楼只请求一次，按文本版本缓存。

**每句都能看情绪、改内容。** 播放按钮旁多了一个情绪按钮，点开悬浮窗的「朗读」面板：能看到这一句被读成什么（场景、情绪、心理、潜台词、停顿、重音……）、最终发给 Fish 的文本和语速音量。文本可以直接改、直接在光标处插标签（情绪下拉、停顿、长停顿、强调、耳语、喊、叹气、倒吸气、抽泣……），像 Fish 官网那样自由插；点「用这个重新生成」只重做这一句，之后整楼朗读也用你改过的版本；「恢复自动」回到副模型的分析。手机上也是同一个面板。

**悬浮窗多了「朗读」页。** 显示正在读第几楼第几段、进度条，按钮：回到上一段、暂停 / 继续、快进到下一段、保存到本地、从头读整楼。楼层底栏也加了暂停和「朗读面板」。「保存到本地」按设置存整楼音频或正在读的那一段（默认跟随模式：全篇存整楼，流式存当前段）；mp3 / opus 直接拼接，wav 会重新写文件头。

**本地音色库。** 给常用的 Fish 音色起名字存起来，全部角色卡共用；旁白、对白默认、每个角色、每门语言的音色都可以从库里选，不用再翻 32 位的 ID。

**一键从角色卡和世界书识别角色。** 副模型读一遍角色卡和世界书条目（标题、关键词、内容片段），返回人物名单和别名，一次导进角色表；副模型没连上就报错，不猜。导进来的角色**跟随对白默认音色**，改默认音色它们一起变；给某个角色填了专属 Voice ID（或从库里选）就**锁定**，之后改默认音色不影响它，「解除绑定」才会解锁。

**没登记音色的角色也会读。** 以前找不到音色直接报错不读；现在没登记的用对白默认音色，连默认音色都没填就不带 `reference_id`，让 Fish 用它自己的默认音色，运行记录里提示一句。

**一个角色可以按语言绑不同音色。** 读中文译文用一个，读日语原文用另一个。句子的语言由副模型判断，没判断时按文字本身（假名、汉字、拉丁字母……）；旁白也可以按语言换音色。

**自定义对白 / 跳过符号。** 「对白符号」决定哪些符号里的是台词（默认 「」『』“”""），「跳过符号」里的内容不读也不挂按钮。比如预设把动作写在星号里：跳过符号填 `* *`，那么 `樱井说：“明天也来吗？” *低头摆弄着衣角*` 只读引号里的话。多字符或相同字符的开合之间空一格（`** **`）。

**自动生成，不播放。** 勾上后最新一楼翻译完成就在后台生成音频，流式模式逐段生成，什么都不播；朗读页也有一个「生成最新一楼的音频（不播放）」按钮。只做最新一楼，翻旧楼不会触发调用。

其他：
- 深度分析附带的背景资料（角色卡 / 世界书 / 前几楼、楼数）可以在朗读页选；复用翻译时的上下文读取逻辑，世界书按当前扫描结果取。
- 「谁说的、什么情绪」现在有四档：跟随模式 / 总是深度 / 总是轻量 / 只用翻译标注。
- 运行记录里 `tts.recording` 记每段音频的单位（整楼 / 第几段 / 单句）、语速音量、时间戳覆盖率；`tts.analysis` 记深度分析的场景和带指令的句数；`tts.cast-import` 记世界书识别结果；`tts.voices` 记谁用了默认音色。
- 旧设置自动迁移：「单句发送」变成「流式朗读」，「副模型分析」变成「跟随模式」。

  - **整篇发送**：一楼只请求一次 `/v1/tts/stream/with-timestamp`。Fish 返回的是逐字（中文）或逐词的时间戳，去掉了标点，数字有时会被读成汉字；镜译把它按字对齐回自己的句子，算出每句的起止时间和音频一起缓存。之后点任何一句都是跳到那一段播放，不再请求。
  - **单句发送**：点哪句只把这一句发给 `/v1/tts`，不为整楼花额度。「朗读本楼」在这个模式下逐句生成、逐句播放，播放当前句时顺手预取下一句。
- **朗读语言**：译文或原文。读原文时按「正文处理」里的提取标签取原文，没翻译过的楼层也能读，日语、英语音色可以直接念原作；Fish 对日文按原文的词对齐（夕暮れ / 教室 / 振り返っ），按句跳转同样准。副模型分析原文时会附上每行译文帮它认人，说话人按译名写，原文里的写法可以加进角色别名。两种语言的音频分开缓存，来回切不会互相覆盖。
- **读什么**：旁白 + 对白 / 只读对白 / 只读旁白。范围决定生成什么，关掉旁白时旁白不会被生成。
- **谁说的、什么情绪**：
  - 「副模型分析」每楼第一次朗读前请求一次，按句标注类型、说话人、情绪和强度，结果按楼层文本版本缓存。引号不再是唯一依据：用引号标书名、专有名词的会被判成旁白，「樱井：好热」这种没有引号的台词会被判成对白。
  - 「只用翻译标注」不额外请求，直接用翻译时副模型给的说话人。分析请求失败时也会退回这个。
- **声音映射**：旁白有独立音色，另有一个对白默认音色；角色 → Voice ID 的表跟着角色卡保存，支持别名，希尔达夫人和希尔达会落到同一个声音上。可以一键导入说话人名单和副模型报过的名字，也可以查询 Voice ID 对应的音色名。
- **转换成 Fish 的格式**：内部先统一成 `{ type, text, speaker, emotion }` 这样的结构，再由 Fish 适配层转换。一个音色时发普通 `reference_id`；多个音色时发 ID 数组，并在换人的位置插入 `<|speaker:N|>`。情绪按强度映射成 S2 的 `[happy]`、`[delighted]`、`[whispering]` 等标签，放在句首；s1 用它自己那套括号标签，而且不支持一次请求多个音色，会按音色自动拆成几段请求。以后接别的 TTS，只需要换适配层。
- **不碰正文**：按钮和底栏只加在渲染后的页面上，楼层 `mes` 一个字不改。播放中的句子用 CSS Custom Highlight 高亮，不给文字包任何标签。宿主重绘楼层后按钮会自动补回。
- **缓存**：音频和分析结果存在浏览器的 IndexedDB 里，不进聊天记录。缓存键由楼层、文本版本、说话人、音色、情绪和所有影响声音的参数组成，改了正文、换了音色或参数都会重新生成；楼层文本变了，旧版本的缓存会被清掉。超过 512 MB 按最久没用的淘汰；浏览器禁用 IndexedDB 时降级为本次会话内存缓存。「朗读」页可以查看用量、清空本聊天或全部缓存。
- **内置美化适配**：可爱风、极简风、原文折叠三款卡片里，播放按钮和高亮换成各自的主色。极简风的按钮平时很淡，读到的句子用下划线标出；底栏会读出这一楼用的是哪款美化，跟着换成对应样式。
- 毛玻璃主题的底部保存栏加了背景模糊，滚动时下面的文字不再透上来叠在一起。
- **修复手机上悬浮入口的圈是歪的。** 手机上的贴边形态以前是「半个球」：42px 高的半胶囊里套着桌面版的进度环，而核心区是 32×40 的长方形，环被挤成 26px 贴在顶上，比铅笔图标高 4px、比外框的圆弧偏左 4px。现在贴边形态按原设计画成贴着右缘的小条（38×34、左侧 10px 圆角），用状态色小圆点代替圆环，翻译进行中底部有一条进度细线。贴边改由样式表 `right: 0` 完成，不再用「窗口宽度减按钮宽度」去算——宽度在形态切换时有动画，量到一半的宽度会让条离开边缘或被切掉。窗口宽度跨过手机断点（横竖屏切换、拖窄浏览器）时形态立刻跟着变，离开贴边形态后回到原来拖到的位置，不会跳到最左边。

**使用前需要打开酒馆的 CORS 代理。** api.fish.audio 不回应浏览器的跨域预检，浏览器没法直接调用。在酒馆目录的 `config.yaml` 里把 `enableCorsProxy` 改成 `true`，重启酒馆，请求会经 `/proxy/` 由你自己的酒馆转发，Key 只发给你的酒馆和 Fish。代理没开时会直接提示怎么改，不会只报一个 404。自建的允许跨域的中转或本地 fish-speech 服务，可以关掉「经酒馆代理」直连。

其他需要知道的：

- Fish 的 API 额度和网页端额度分开计算。API 余额为 0 时 s2-pro 会返回余额不足；免费开发者档用 `s2.1-pro-free`，同样支持多说话人。「测试连接」会显示当前 API 余额，不会产生合成费用。
- 默认格式 mp3，兼容性最好；opus 体积更小，但旧版 Safari 可能播不了。
- 已知限制：「只用翻译标注」时一行只有一个说话人，一行里两个人说话会用同一个声音。渲染后文字和译文差异太大（比如预设的正则改写了译文）时，个别句子找不到位置就不挂按钮，运行记录里会写明是哪一楼，「朗读本楼」照常能读。
- 运行记录新增 `tts.analysis`、`tts.floor-part`、`tts.sentence` 等条目：分析请求和返回、每段音频的时间戳覆盖率、没对上时间戳的句子都在里面；Key 不会进日志。

## v0.15.6 · 名单外的说话人也有颜色

上一版修的是「原文行自带 `<span style="color:">`，译文丢掉」那条路。实际反馈的掉色不走那条：楼层里写着

```
<span class="jy-spk jy-emo-happy jy-emo-l1" title="喜悦" style="font-weight:460 !important">
```

没有 `jy-spk-xxxx` 类名、`style` 里一个 `color:` 都没有、`title` 只有情绪没有名字——副模型认出了说话人，但那个名字不在说话人名单里，于是颜色被整条滤掉，只剩情绪的字重和斜体。着色功能在登记完全部角色之前等于不工作，而且一声不响。

- **名单外的说话人按名字自动取色**（默认开，正文处理 · 说话人着色）。复用原本给黑白银发色角色兜底的那套：名字哈希出一个固定色相，再钳进当前主题算出的安全色域。同一个名字在任何设备、任何聊天里都是同一个颜色。之后把这个人登记进名单并填上真实发色，就从自动取色换成按发色取色；名单里的人仍然单独做色相分散，名单外的不参与，免得中途冒出一个新名字把已经在屏幕上的人全部重新上色。
- **不再闷声失败**。三种原因（「说话人着色」没勾、名字不在名单、自动取色关掉）在屏幕上长得一模一样，现在正文处理页直接列出上一楼报出的每个说话人、各占几段、拿到了什么颜色；没上色的用虚线 chip 标出来并写明是哪一种原因。运行记录同时留一条 `coloring.speaker-unpainted`。
- **一键登记**。报告下面的「把这 N 个名字加进名单」把副模型报出来的名字直接建成色板行，颜色保持不变，之后填发色即可。
- 翻译一结束报告就会刷新，不用再点一次别的开关才看得到。

已知限制（原有设计，不是这次的问题）：几行之间没有空行时会合并成一个翻译单位，只要里面混了没有说话人标注的旁白，整块就不上色——一块里两个说话人没法分开上色。行与行之间有空行则不受影响。

## v0.15.5 · 译文不再掉色，以及能看模型在想什么

- **修复「翻译对话会掉色」**。原文那一行被预设包在 `<span style="color:…">` 里时，译文写回来是裸的：送给副模型之前所有标签都必须剥掉，否则它会开始翻译标签本身——但剥掉之后从来没有还回去。于是预设给对话上的颜色只剩原文一半，旁白反而看不出差别，读起来就像「翻译把对话的颜色弄掉了」。现在**整行**被包裹时，译文那一行会套回同一层（正文处理 · 段落前后缀 ·「译文跟随原文格式」，默认开）。
  - 只认整行包裹的表现型标签：`span` `font` `b` `strong` `i` `em` `u` `s` `mark` `small` 这些。两个并列的 `<span>` 不算（没有单一包裹），`<div>` 不碰（块级会改版式），`<a>` 不碰（不能给译文凭空加个链接）。
  - 只带 `style` / `color` / `class` / `size` / `face`，`id`、`onclick` 之类一概丢掉——复制一份行为到第二个元素上不是翻译该做的事。
  - 按行走，不按段走：一段里只有对话那行有颜色，就只有对话那行跟随。
  - 开了说话人着色时，颜色以说话人为准（不然就是外层那个静静地输掉），粗体斜体仍然跟随。
  - 剥离不变：主模型看到的仍然是一字不差的原文，补译读回来的仍然是干净译文。
- **能看模型到底在想什么**。翻译台的「副 API 正在思考（已 N 字）」下面多了一块实时的思考内容：思考期间自动展开、只画尾巴、自动滚到底、顶部渐隐，左边一个呼吸的点；译文一开始输出就自动折叠成一行「本批思考过程 N 字 · 第 X 批」，点一下展开看全文。手动点过之后以你点的为准，下一批重置。
  - 运行记录里每条返回多了「查看模型思考」，用正文排版而不是等宽 JSON，带独立的复制按钮；「导出日志」也会带上，单独成段，不混进请求和返回里。
  - 流式和整包两条路都捞：`reasoning_content` / `reasoning` / `thinking` 都认，藏在 `choices[0].message` 里也能挖出来。
  - 思考只是证据，永远不进译文、不进楼层、不进安全摘要（它带正文）。

## v0.14.0 · 说话人着色与情绪排版

副模型只回答「这一段谁在说、什么情绪」，颜色和排版全部由镜译在本地算出。这样做是因为：让模型直接吐颜色，等于要它同时完成四件事——认出说话人、记住这个人的颜色、生成合法标记、还要判断这颜色在它看不见的主题上是否可读。四件里只有第一件是模型稳定做得好的。改成输出标签之后，它只剩下一个分类任务，而且结果可以校验：说话人必须在名单里，情绪必须在枚举里，写错就退回普通样式，绝不会污染正文。

- **读取当前主题与壁纸**（正文处理 · 说话人着色）。取样聊天区实际渲染出来的背景——壁纸像素、主题半透明底色、模糊层，全部合成之后取暗部、中位、亮部三处，再算出在这三处都能达到对比度目标的明度方向与最大彩度。这就是「可用颜色范围」。背景是中灰壁纸这类真的无解的情况会直接说清楚，并给出一个能用的对比度数字，而不是硬算出一堆灰字。
- **说话人着色按发色 / 瞳色**。只取来源颜色的色相，明度由当前背景重新解出来：同一个角色在深色主题和浅色主题下色相不变、明暗自动翻转，换主题只需要重新取一次色。黑、白、银按你的规则排除——这三种是主题自己的文字颜色，认不出说话人；发色是黑白银的角色按名字哈希分到一个固定色相，同一个名字在任何设备任何聊天里都是同一个颜色。发色相近的角色（两个金发）会被自动拉开色相间距。
- **情绪排版**。12 个固定情绪标签映射到字重、斜体、字号、字间距和颜色微调，强度分 0/1/2 三档。所有微调都会重新过一遍对比度检查，任何情绪、任何强度都不可能把一行压到读不清。模型答英文、中文或近义词（furious / 愤怒 / 恼火）都能对上；认不出来就当没标注。
- **样式走两条通道**。每段译文既带内联 style，也带 `jy-spk-xxx` / `jy-emo-xxx` 类名，类名对应的颜色由镜译注入一张样式表。宿主哪天开始过滤内联样式，颜色也还在；重新取一次色就能给已有全部楼层换色，不用改写任何一条消息。
- **样式不进主模型**。着色标记写在原有的不可见边界内，与前后缀走同一套剥离逻辑：主模型看到的仍然只有原文，剥离后的楼层与关闭着色时逐字节相同。

## v0.13.4 · 修复四条偶发问题与流式入口语义

针对用户反馈的四条「偶现」问题，逐条给出了可复现的成因与修复；每条都有对应的回归测试。

- **流式写回偶尔不生效**。四个独立成因：
  - 跟随模式下的自动回退引用了不存在的变量 `options`，直接抛 `ReferenceError`（P0）。
  - 已译完的楼层点「翻译当前回复」时，流式路径永远以现有译文为种子，每批待译段落都是空的，于是一段都不请求却照样报「翻译完成」。现在流式与整包共用同一套 force / quiet 语义：主按钮强制重翻，补译按钮只补缺口。
  - 悬浮小窗的「翻译 / 补译」从来只走整包，勾选流式也没用。所有入口（翻译台、小窗、自动翻译、滑动补译、编辑重翻）统一走同一个调度函数。
  - 反代忽略 `stream` 参数、直接返回一个普通 JSON 响应时，流式读取拿不到任何 SSE 帧，却返回空字符串而不是报错，导致整包回退不触发、楼层一字未改也没有任何报错。现在会按整包结果解析，并在运行记录留下说明。
- **偶现的双重前后缀标签**。楼层里的不可见边界一旦被外部清理（编辑保存、剪贴板、第三方正则）而可见的 `<jy-source>` 之类前后缀留了下来，下一次翻译就会在外面再套一层。现在会依据楼层元数据识别并清除这种残留；符号型前后缀（`☆{`、`{`）无法与正文自带标点区分，不做猜测，只在运行记录里报告。
- **偶现的注入时连带译文注入**。除生成拦截器与提示词事件之外，新增第三道防线：四条 `promptOnly` 原生正则，凡是走酒馆自身正则层的提示词路径都会被清掉镜像块，即使拦截器完全没被调用也不会泄漏。同时，译名强制激活世界书不再在 quiet / impersonate 等旁路生成中排队，避免激活留到下一次真实回复。
- **分行时中间多出很多空行**。`restyleBilingual` 会把「每行单独成段」的分隔空行搬到后缀外面，使收尾标签单独占一行、美化正则多吃一个空行；现在换样式对未改动的楼层是逐字节相同的。另外补了 4000 组随机版式的回环测试，确认任何版式（含部分译）剥离后都能还原成完全一致的原文。

其余按技术审查报告修复：

- 替换标签部分写回后，补译种子按下标配对，会把第 N 段的译文塞给第 N-1 段并覆盖好段落；改为按隐藏原文配对。
- 日志脱敏规则把 `requestTokens` 当成凭据抹掉，token 数一行永远渲染不出来；统计类字段改为白名单放行，真实凭据仍然隐藏。
- 流式请求没有应用连接的超时设置，连接建立后可以无限等待；现在与整包路径共用同一个超时。
- 世界书只读 `globalLore` + `characterLore`，聊天世界书和 Persona 世界书既进不了节约模式白名单也点不着译名激活；四类来源全部纳入并去重。
- 节约模式白名单直接发送 `entry.content`，`{{char}}` / `{{user}}` 等宏原样进入副模型；现在在副本上做宏展开。
- 译名强制激活只用 `includes` 子串匹配，与酒馆原生语义不等价；现在支持 `/正则/` 关键词、`caseSensitive`、`matchWholeWords`，带次要关键词的选择性条目一律交还酒馆判定，宁可漏激活也不越权。
- 「检查当前楼层」现在把替换标签一起纳入，常见的 `<story_scene><status>…</status></story_scene>` 嵌套在预检阶段就会报出来，而不是等到翻译时才失败。
- 流式渐进写回改为串行队列并逐步拉长间隔（0.7s 起，最多 4s）：此前多次写回可能并发，其中一次 saveChat 失败会把楼层回滚到更旧的内容。

```text

```

安装步骤：

1. 打开 SillyTavern 的“扩展”。
2. 点击“安装扩展”。
3. 粘贴上面的 Git URL。
4. 安装完成后刷新 SillyTavern。

安装后可在控制中心点击“检查更新”。发现新版时再次点击安装，完成后手动刷新酒馆。更新过程调用酒馆自带的扩展 Git 接口；宿主不提供该接口时，可使用酒馆扩展管理页更新。入口、样式与内部模块携带版本地址，避免更新后混用旧模块。

扩展会同时提供三个入口：

- 魔法棒菜单中的“镜译 · 正文翻译器”；
- 扩展设置页中的“打开控制中心”；
- 默认显示的可拖动“译”悬浮入口；可以在设置页关闭。

它不依赖 TavernHelper，也不需要另行导入提示词过滤正则。

## 第一次使用

1. 保证预设让主模型只输出原文，并将正文放在 `<story_scene>...</story_scene>` 中。
2. 在控制中心的“设置”页选择翻译通道：
   - “跟随当前连接”：使用当前聊天 API 与模型；
   - “独立副 API”：新建或选择一个预设，填写 OpenAI 兼容基础地址和密钥，再点击“拉取模型列表”。插件会展示完整列表并等待你明确选择，不会擅自采用排序后的第一个模型；接口不提供列表时仍可手动填写模型名。请求由 SillyTavern 服务端代理，不会改变主聊天连接。
3. 点击“测试翻译通道”。
4. 保持“主回复完成后翻译”开启。

默认只提取 `story_scene`。如一条回复里还有其他正文标签，可在设置页逐行添加标签名；`story_scene` 和 `<story_scene>` 两种写法都能识别。也可以逐行添加排除标签，排除块会留在原文原位，但不会交给翻译通道。

“原样保留白名单”用于处理分隔框、已有标题或其他整行结构。普通条目匹配整行，`prefix:` 匹配行首，`/正则/` 匹配原始整行；命中的行不建立翻译编号，也不会发送给副 API。纯边框、纯符号和只有标签的行会自动保留。设置页的“检查当前楼层”会报告正文标签末组、排除块、空行段落、实际翻译行、白名单命中以及透明结构标签。

0.3.x 中填写过的独立地址、密钥、模型、温度、输出长度和超时会自动迁移成一个副 API 预设，不需要重新填写。

## 翻译方案、固定姓名与上下文

### 正文处理方案

正文处理页顶部选择方案，页尾保存设置。「管理」里可以改名、删除；「导出方案」打包当前设置和完整正则，「导入方案」新增一套方案。文件不含 API 连接、密钥或聊天记录。

在页底「绑定正则」中直接导入酒馆导出的单条或批量 JSON，也可以多选文件。导入后自动绑定当前方案，列表支持开关、排序和解除绑定。规则由酒馆原生正则执行；切换方案只替换镜译管理的规则组，其他正则保持原有设置。在酒馆正则管理器修改绑定规则后，镜译保存或导出时会读取这些修改。

「内置美化」提供可爱风、极简风、原文折叠。使用时创建对应方案，提取标签、排除标签、白名单与其他开关沿用当前值。更改外观会复用当前聊天各滑动页已有的译文；提取与排除规则在后续翻译时采用。

### 翻译要求

“提示词”页把翻译要求整理成可保存、复制和切换的翻译方案。每个方案都保存自己的目标语言；来源语言不需要手填，会按待译段落自动识别。标准条目默认收起，点击铅笔才会展开编辑：

- 置顶的可选前置提示词（空白时不发送）；
- 核心翻译规范；
- 翻译文风；
- 称谓与角色口吻；
- 未知姓名与专名；
- 对话与标点；
- 禁用表达 / 杀八股；
- 姓名与术语表；
- 正例与反例；
- 输出前检查清单。

文风、称谓、未知姓名和标点既有内置选项，也能切换成自定义规则。页面底部还能添加、排序、复制、停用或删除任意自定义条目。姓名、地名或私设译名不会作为插件默认内容，需要时由使用者写进术语表。

简体中文目前拥有完整的内置文风、称谓、专名、标点和杀八股规则包。其他目标语言使用通用翻译规范，并继续执行使用者填写的自定义规则；插件不会假装提供尚未完成的韩语、英语等专门规则包。核心规范、检查清单、前置提示词和自定义条目都可以使用 `{{source_language}}`、`{{target_language}}`、`{{translation_direction}}` 三个变量。

界面虽然按主题拆开，实际请求不会把每一项拆成大量零散消息。一次翻译只发送：可选前置提示词、一份合并后的翻译规范、一份检查清单，以及一个包含参考资料和待译段落的数据包。正常的首次请求会把本轮所有选中正文一起交给副 API，不会按段落拆成多次调用。模型返回的 `<thinking>` / `<think>` 检查内容只用于解析结构，不会写进聊天正文。

默认请求还会携带当前角色显示名、角色卡设定、本轮激活的世界书和近期对话。世界书与前文只用于识别专名和语境，不允许把参考资料中未出现在目标原文里的内容补进译文。若某个原创名字必须使用指定写法，仍建议把它明确写进姓名与术语表；仅靠读音本身通常无法唯一推断正确译名。

## 当前行为

- 默认正文标签：`story_scene`，支持逐行配置多个正文标签；
- 同名正文标签出现多次时，只处理该标签最后一组完整内容；不同标签各自选中最后一组，并在一次首次请求中共同送译；
- 支持多个排除标签；嵌套排除块和自闭合排除标签保持原样、不会进入待译文本；
- 支持转义与未转义的结构标签；非排除标签只保留标签外壳，标签名和属性不会进入副 API，内部正文仍正常翻译；
- 支持原样保留白名单的整行、行首和正则规则；无效正则会在保存或检查时指出具体行号；
- 自动处理新回复和已有滑动页；
- 只在一次真实角色生成的最终楼层渲染后自动触发；切换聊天或停止生成会取消旧任务；
- 编辑后自动重译默认关闭；
- 正文以完整空行为段落边界；段内每个实际语义行在同一批请求中独立编号，写回时仍合并为一个目标语言镜像块，因此原有换行不会被模型压平；首尾空行也会原样保留；
- 可以给每个空行段落原样附加自定义前缀与后缀，例如 `<small>` 和 `</small>`；扩展不规定其显示效果；
- 接受 JSON 代码围栏、乱序 ID、`text/chinese/translation` 字段差异、外层花括号和少量换行等常见格式噪声；
- 失败后自动重试次数默认是 1，并由一个设置统一控制请求失败、缺段恢复、正文变化后重译和保存失败后的安全重试；不会因此把正常首次请求拆成逐段调用；
- 整次结果不完整时保留已经成功的段落，只向副模型补译缺失编号；补译结束后仍不完整，会把可恢复译文写回，缺失段保留原文并允许再次继续；
- 外层 JSON 即使被截断，也会扫描并恢复其中所有已经闭合的译文条目；
- “尽量避免”词只约束模型不凭空添加；“绝对禁用”词命中时只对受影响段落进行一次针对性修正，修正失败不会丢掉完整的首次译文；
- 首次调用始终把本轮全部选中正文一次性交给副 API，不按字符数或段落数拆批；只有返回不完整或命中绝对禁用表达时，才会按设置进行恢复或定向修正；
- 独立副 API 可以保存多套预设、拉取完整模型列表、明确选择或手动填写模型，并按预设排除不兼容的请求参数；
- API 返回期间会重新读取最新楼层：聊天、滑动页或真正的待译正文变化时旧结果不会直接写回；只新增排除标签内容或正文标签外内容时，译文会安全合并到最新楼层，不会覆盖文生图插件后来插入的内容；
- 同一楼层同一滑动页只允许一个镜译任务；自动事件只排入下一个事件循环，不设置固定等待，也不会持续监听并反复抢写；
- 目标语言镜像由扩展内置生成拦截器从主模型 prompt 中移除。
- “日志”页同时提供安全诊断摘要和完整返回记录。每次副 API 成功返回的 `content`、`reasoning` / `thinking` 会完整保存在本机并默认收起，可单独复制或随完整报告复制；安全摘要不会包含这些正文。凭据字段和常见密钥格式仍会隐藏。为避免撑满浏览器存储，超过总量上限时会整条淘汰最旧记录，不截断保留下来的单条响应。

## 隐私与网络

翻译文本以及你启用的提示词条目、固定译名、例文、角色设定、激活世界书和近期对话会发送到你选择的当前 API 或独立副 API。独立通道的地址、密钥、模型和预设保存在当前 SillyTavern 用户设置中，密钥由当前 ST 服务端用于向对应地址转发请求。为了诊断空回、截断和格式漂移，完整副 API 返回也会保存在当前浏览器的镜译日志中，可能包含正文与模型思考；“复制完整日志”后发送给别人前必须自行检查隐私内容。“复制安全摘要”不会带这些完整返回。扩展自身不包含远程统计、广告或额外遥测。
