# 镜译 · 正文翻译器

## v0.13.1 · 流式写回改为可勾选模式

- 「流式翻译」从独立按钮改为「流式写回」勾选项（翻译台 · 自动接续翻译区）。勾选后所有翻译——包括主回复完成后的自动翻译、切换滑动页补译、编辑重翻和手动翻译——都走流式路径；不勾选则全部走整包路径。跟随模式下勾选会自动回退整包并在运行记录注明。

## v0.13.0 · 流式写回、替换标签与节约模式

- 新增「流式翻译」（beta，仅独立模式）：请求内容与整包翻译完全一致、token 消耗不变，译文随流式返回逐步写进楼层，收尾走同一套修正与写回管线，最终结果与整包翻译一致；渠道流式中断时自动回退整包重试。
- 新增「替换标签」：该标签内的内容照常翻译，写回时译文直接顶替原文——显示与主模型提示都只看到译文，原文隐藏保留在楼层文本里（点小铅笔可见），重新翻译时自动还原，与提取标签可在同一楼层混用。前后缀与每行成段对替换区域不生效。
- 新增「节约 token 模式」（按连接保存）：世界书只注入白名单条目（白名单按角色卡分别保存、切换跟随），近期对话锁上限 2 楼；不勾白名单则完全不带世界书。近期对话默认条数改为 2（上限仍 20）。
- 译文现在可以触发世界书：主模型生成时，酒馆扫描的是剥离译文后的文本，译名（如译文里的「英梨梨」）原本永远点不着条目；现在拦截时会按译文名词强制激活匹配的世界书条目，仅影响主流程，镜译自己的参考资料不变。
- 渠道参数新增「推理强度」（不发送 / minimal / low / medium / high）；翻译方案新增「后置提示词」：留空不发送，填写后作为最后一条消息附在全部条目之后，身份可在 user / system / assistant 间选择。
- 运行记录合并为「导出日志」抽屉：可选导出最近 X 楼或全部楼层（TXT 下载），原三个复制按钮移除。每条返回记录现在直接显示本次请求的 token 数（渠道返回 usage 时为实测，否则按字符估算）。

## v0.12.9 · 日志导出 TXT

- 运行记录新增「导出 TXT」按钮，把完整日志（含副 API 请求与返回正文）直接下载为 txt 文件，不再依赖剪贴板；文件名带时间戳，已做 Windows 记事本兼容。内容与「复制完整日志」一致，分享前请检查隐私。

## v0.12.8 · 分批只看字符预算与全量参考资料

- 分批不再受隐藏的每批段数上限（100 段）约束，此前对话密集型楼层即使输出上限充裕也会被切成多批，且调大 maxTokens 毫无作用。现在只按字符预算切批，token 到字符的换算系数从 0.35 放宽到 0.8，预算上限提高到 160000。
- 参考资料不再截断。此前词汇表、角色卡、世界书、近期对话分别被悄悄截到 5000/7000/14000/10000 字符，重度世界书用户译文质量受损而无从排查；现在全量发送。
- 「翻译当前回复」「翻译本楼」改为先终止该楼层进行中的旧任务再按当前设置重新开始，此前点击会被静默并入旧任务，看到的仍是旧设置的结果；并入补译时会有提示。
- 「补译缺失段落」按钮回归翻译台。v0.12.1 承诺的该按钮在 v0.12.0 面板重构中丢失，只补空缺段落、不重翻已有译文。
- 超时默认 240 秒（上限仍 600），自动重试上限放宽到 5 次，运行记录单条消息截断放宽到 2000 字符。

## v0.12.7 · 输出上限放开与窄屏修复

- 「最大输出 tokens」默认值改为 60000，保存上限不再压在 32768：填多少就按多少换算每批字符预算，大输出渠道的请求次数进一步减少。已保存的连接保持原值不变。
- 修复窄屏（≤640px）下正文处理页横向溢出：「悬浮入口形态」下拉框会按最长选项撑开自身宽度，把整个面板顶出手机屏幕，导致可以横向/斜向拖动、点击折叠栏目时误触遮罩层而整个面板关闭。现在该下拉框在窄屏下允许收缩，面板宽度始终压在屏幕内。
- 正文处理页的「提取正文 / 保留原样」双栏在窄屏下改为上下堆叠，与其他页面的窄屏行为一致。

## v0.12.6 · 每行单独成段与批次上限

- 「对每一行分别添加前后缀」改为「每行单独成段」。勾选后每一行都独立成段，原文与译文逐行贴在一起，每对之间空一行；用于分隔的空行写在不可见边界内，主模型看到的原文与分行方式保持不变。
- 分批不再受固定的每批 20 段限制。每批段数由副 API 的输出上限换算，输出上限调高后请求次数明显减少。

## v0.12.5 · 缺少结束标签也能翻

- 正文标签只有开头没有结尾时，把开标签之后到楼层末尾的内容当作正文，不再直接报错。有成对闭合的标签组时仍然优先使用完整的那组。
- 「检查当前楼层」会说明本楼是按哪种方式识别的正文。

## v0.12.4 · 逐行前后缀与标签容错

- 段落前后缀新增「对每一行分别添加前后缀」开关。不勾选与之前完全一致，勾选后每行各加一次，分段逻辑不变。
- 正文标签多出一个落单的开标签或结束标签时，不再整楼放弃。已经成对闭合的那几组照常使用，落单的部分在「检查当前楼层」里单独提示。此前只要出现一个多余的 `<story_scene>`，整次提取就会失败且没有补救手段。
- 完全没有成对标签时的提示区分「没有成对闭合」和「没有找到标签」两种情况。

## v0.12.3 · 旧版兼容与失败可诊断

- 不再依赖 `minimum_client_version`。宿主没有调用生成拦截器时，改用提示词事件移除译文镜像块，旧版酒馆同样不会把译文带进主模型；两条路都不可用时才报错提示。
- 副 API 请求失败时记录完整请求与错误内容。此前抛异常的分支什么都不记，只弹出一句无从排查的提示。
- 形如 `<none>` 的不透明错误会补上说明并指向运行记录，不再只显示一个孤零零的词。
- 副 API 返回中不含任何可用译文时单独记一条日志。
- 译文里的 `<none>`、`N/A` 等占位符视为缺失，交给补译，不再写进楼层。
- 翻译期间正文变化时，保留原文未变的段落的译文，其余留待补译，不再整单丢弃。

## v0.12.2 · 日志导出

- 运行记录新增「复制本楼日志」，只导出当前楼层的记录。
- 完整日志现在同时包含发送给副 API 的请求，此前只记录返回，缺段和空回没法对着请求排查。
- 「复制安全摘要」仍然不含请求与返回正文，可以直接贴给别人。

## v0.12.1 · 长楼层分批与宿主自检

- 长楼层不再一次性发给副 API。请求按副 API 的输出上限拆批，某一批没有新增译文时自动折半重试，并设有总请求次数上限。此前 40 段以上的楼层几乎必然被输出上限截断，补译又把剩余段落原样重发，于是大量段落停留在原文。
- 翻译台与悬浮窗新增「补译缺失段落」按钮，保留已有译文只补空缺。
- 宿主未调用生成拦截器时会明确报错提示。此前译文会随提示词静默进入主模型上下文，导致正文劣化。
- 「检查当前楼层」区分「标签尚未闭合」与「未找到标签」，正文仍在生成时不再误报找不到标签。

## v0.12.0 · 正文方案与自由前后缀

- 译文不再强制包上花括号。默认前后缀仍是 `{` 和 `}`，可以修改或留空；升级时保留原先的实际显示效果。
- 主模型过滤译文和镜译添加的原文前后缀。过滤依靠内部边界，即使可见前后缀全为空也有效；原文自带的相同符号会保留。
- 正文处理页有独立方案，默认名称为「默认」。整页设置和绑定的酒馆原生正则一起保存、切换、导入和导出；已有译文立即换样式，无须重新翻译。
- 原有设置下方收纳「绑定正则」和「内置美化」。可爱风、极简风、原文折叠三款样式按需选用，原文折叠可展开，译文缩进显示。
- 移除 `minimum_client_version`，兼容没有激活钩子的旧版加载方式；实际功能按宿主提供的接口运行，不再按版本号拒绝加载。

## v0.9.0

更紧凑的深色界面、模型搜索，以及重新编写的通用翻译规范与简短核对清单。提示词条目仍默认收起，点击铅笔编辑。

未修改的旧默认规范会自动升级。自定义规范保留原样；需要切换时，在提示词页点击“采用新版规范与清单”，原方案会备份，文风、术语表和自定义条目继续保留。

面向 SillyTavern 的浏览器侧扩展。主模型只生成正文标签中的原文，镜译在回复完成后自动识别各段来源语言，并把翻译方案中指定的目标语言按空行段落写回。默认目标语言仍是简体中文：

```text
夕暮れの教室には、誰もいなかった。
窓から差し込む光が、机を淡く照らしている。
{傍晚的教室里，一个人也没有。
窗外照进来的光，淡淡地照着桌子。}
```

示例中的花括号是可编辑的显示设置。原文与译文另带不可见边界，扩展据此在主模型生成前移除镜译添加的原文装饰与整个译文块，聊天界面仍保留双语。旧聊天会结合当时保存的元数据迁移；缺少旧元数据时仍过滤带标记的译文，不猜测普通原文符号的归属。

## 安装

安装地址：

```text
https://github.com/iabil-604/MirrorTranslate.git
```

安装步骤：

1. 打开 SillyTavern 的“扩展”。
2. 点击“安装扩展”。
3. 粘贴上面的 Git URL。
4. 安装完成后刷新 SillyTavern。

安装后可在控制中心点击“检查更新”。发现新版时再次点击安装，完成后手动刷新酒馆。更新过程调用酒馆自带的扩展 Git 接口；宿主不提供该接口时，可使用酒馆扩展管理页更新。入口、样式与内部模块携带版本地址，避免更新后混用旧模块。

扩展会同时提供三个入口：

- 魔法棒菜单中的“镜译 · 正文翻译器”；
- 扩展设置页中的“打开控制中心”；
- 默认显示的可拖动“译”悬浮入口；可以在设置页关闭。

它不依赖 TavernHelper，也不需要另行导入提示词过滤正则。

## 第一次使用

1. 保证预设让主模型只输出原文，并将正文放在 `<story_scene>...</story_scene>` 中。
2. 在控制中心的“设置”页选择翻译通道：
   - “跟随当前连接”：使用当前聊天 API 与模型；
   - “独立副 API”：新建或选择一个预设，填写 OpenAI 兼容基础地址和密钥，再点击“拉取模型列表”。插件会展示完整列表并等待你明确选择，不会擅自采用排序后的第一个模型；接口不提供列表时仍可手动填写模型名。请求由 SillyTavern 服务端代理，不会改变主聊天连接。
3. 点击“测试翻译通道”。
4. 保持“主回复完成后翻译”开启。

默认只提取 `story_scene`。如一条回复里还有其他正文标签，可在设置页逐行添加标签名；`story_scene` 和 `<story_scene>` 两种写法都能识别。也可以逐行添加排除标签，排除块会留在原文原位，但不会交给翻译通道。

“原样保留白名单”用于处理分隔框、已有标题或其他整行结构。普通条目匹配整行，`prefix:` 匹配行首，`/正则/` 匹配原始整行；命中的行不建立翻译编号，也不会发送给副 API。纯边框、纯符号和只有标签的行会自动保留。设置页的“检查当前楼层”会报告正文标签末组、排除块、空行段落、实际翻译行、白名单命中以及透明结构标签。

0.3.x 中填写过的独立地址、密钥、模型、温度、输出长度和超时会自动迁移成一个副 API 预设，不需要重新填写。

## 翻译方案、固定姓名与上下文

### 正文处理方案

正文处理页顶部选择方案，页尾保存设置。「管理」里可以改名、删除；「导出方案」打包当前设置和完整正则，「导入方案」新增一套方案。文件不含 API 连接、密钥或聊天记录。

在页底「绑定正则」中直接导入酒馆导出的单条或批量 JSON，也可以多选文件。导入后自动绑定当前方案，列表支持开关、排序和解除绑定。规则由酒馆原生正则执行；切换方案只替换镜译管理的规则组，其他正则保持原有设置。在酒馆正则管理器修改绑定规则后，镜译保存或导出时会读取这些修改。

「内置美化」提供可爱风、极简风、原文折叠。使用时创建对应方案，提取标签、排除标签、白名单与其他开关沿用当前值。更改外观会复用当前聊天各滑动页已有的译文；提取与排除规则在后续翻译时采用。

### 翻译要求

“提示词”页把翻译要求整理成可保存、复制和切换的翻译方案。每个方案都保存自己的目标语言；来源语言不需要手填，会按待译段落自动识别。标准条目默认收起，点击铅笔才会展开编辑：

- 置顶的可选前置提示词（空白时不发送）；
- 核心翻译规范；
- 翻译文风；
- 称谓与角色口吻；
- 未知姓名与专名；
- 对话与标点；
- 禁用表达 / 杀八股；
- 姓名与术语表；
- 正例与反例；
- 输出前检查清单。

文风、称谓、未知姓名和标点既有内置选项，也能切换成自定义规则。页面底部还能添加、排序、复制、停用或删除任意自定义条目。姓名、地名或私设译名不会作为插件默认内容，需要时由使用者写进术语表。

简体中文目前拥有完整的内置文风、称谓、专名、标点和杀八股规则包。其他目标语言使用通用翻译规范，并继续执行使用者填写的自定义规则；插件不会假装提供尚未完成的韩语、英语等专门规则包。核心规范、检查清单、前置提示词和自定义条目都可以使用 `{{source_language}}`、`{{target_language}}`、`{{translation_direction}}` 三个变量。

界面虽然按主题拆开，实际请求不会把每一项拆成大量零散消息。一次翻译只发送：可选前置提示词、一份合并后的翻译规范、一份检查清单，以及一个包含参考资料和待译段落的数据包。正常的首次请求会把本轮所有选中正文一起交给副 API，不会按段落拆成多次调用。模型返回的 `<thinking>` / `<think>` 检查内容只用于解析结构，不会写进聊天正文。

默认请求还会携带当前角色显示名、角色卡设定、本轮激活的世界书和近期对话。世界书与前文只用于识别专名和语境，不允许把参考资料中未出现在目标原文里的内容补进译文。若某个原创名字必须使用指定写法，仍建议把它明确写进姓名与术语表；仅靠读音本身通常无法唯一推断正确译名。

## 当前行为

- 默认正文标签：`story_scene`，支持逐行配置多个正文标签；
- 同名正文标签出现多次时，只处理该标签最后一组完整内容；不同标签各自选中最后一组，并在一次首次请求中共同送译；
- 支持多个排除标签；嵌套排除块和自闭合排除标签保持原样、不会进入待译文本；
- 支持转义与未转义的结构标签；非排除标签只保留标签外壳，标签名和属性不会进入副 API，内部正文仍正常翻译；
- 支持原样保留白名单的整行、行首和正则规则；无效正则会在保存或检查时指出具体行号；
- 自动处理新回复和已有滑动页；
- 只在一次真实角色生成的最终楼层渲染后自动触发；切换聊天或停止生成会取消旧任务；
- 编辑后自动重译默认关闭；
- 正文以完整空行为段落边界；段内每个实际语义行在同一批请求中独立编号，写回时仍合并为一个目标语言镜像块，因此原有换行不会被模型压平；首尾空行也会原样保留；
- 可以给每个空行段落原样附加自定义前缀与后缀，例如 `<small>` 和 `</small>`；扩展不规定其显示效果；
- 接受 JSON 代码围栏、乱序 ID、`text/chinese/translation` 字段差异、外层花括号和少量换行等常见格式噪声；
- 失败后自动重试次数默认是 1，并由一个设置统一控制请求失败、缺段恢复、正文变化后重译和保存失败后的安全重试；不会因此把正常首次请求拆成逐段调用；
- 整次结果不完整时保留已经成功的段落，只向副模型补译缺失编号；补译结束后仍不完整，会把可恢复译文写回，缺失段保留原文并允许再次继续；
- 外层 JSON 即使被截断，也会扫描并恢复其中所有已经闭合的译文条目；
- “尽量避免”词只约束模型不凭空添加；“绝对禁用”词命中时只对受影响段落进行一次针对性修正，修正失败不会丢掉完整的首次译文；
- 首次调用始终把本轮全部选中正文一次性交给副 API，不按字符数或段落数拆批；只有返回不完整或命中绝对禁用表达时，才会按设置进行恢复或定向修正；
- 独立副 API 可以保存多套预设、拉取完整模型列表、明确选择或手动填写模型，并按预设排除不兼容的请求参数；
- API 返回期间会重新读取最新楼层：聊天、滑动页或真正的待译正文变化时旧结果不会直接写回；只新增排除标签内容或正文标签外内容时，译文会安全合并到最新楼层，不会覆盖文生图插件后来插入的内容；
- 同一楼层同一滑动页只允许一个镜译任务；自动事件只排入下一个事件循环，不设置固定等待，也不会持续监听并反复抢写；
- 目标语言镜像由扩展内置生成拦截器从主模型 prompt 中移除。
- “日志”页同时提供安全诊断摘要和完整返回记录。每次副 API 成功返回的 `content`、`reasoning` / `thinking` 会完整保存在本机并默认收起，可单独复制或随完整报告复制；安全摘要不会包含这些正文。凭据字段和常见密钥格式仍会隐藏。为避免撑满浏览器存储，超过总量上限时会整条淘汰最旧记录，不截断保留下来的单条响应。

## 隐私与网络

翻译文本以及你启用的提示词条目、固定译名、例文、角色设定、激活世界书和近期对话会发送到你选择的当前 API 或独立副 API。独立通道的地址、密钥、模型和预设保存在当前 SillyTavern 用户设置中，密钥由当前 ST 服务端用于向对应地址转发请求。为了诊断空回、截断和格式漂移，完整副 API 返回也会保存在当前浏览器的镜译日志中，可能包含正文与模型思考；“复制完整日志”后发送给别人前必须自行检查隐私内容。“复制安全摘要”不会带这些完整返回。扩展自身不包含远程统计、广告或额外遥测。
